# Isometric diagram set

A parallel, data-driven diagram set. It does **not** replace
[`../diagrams/`](../diagrams/) — see the comparison at the end.

The distinguishing property: **every coordinate in the layered views is a real link
midpoint from `pos`, projected isometrically.** These are not illustrations of the Paris
network, they are the Paris network. Regenerating them after a data change changes the
picture, which is the point.

```
sx = (x - y) * cos(30°)
sy = (x + y) * sin(30°) - z
```

Generated by `scripts/figure_generation/generate_isometric_diagrams.py`.

| File | Shows | Data behind it |
| --- | --- | --- |
| `iso_01_graph_lifting.svg` | The same 5,200 links seen twice: as geography, and lifted into the line graph above it | `pos[:, 2]` for both planes; real `edge_index` pairs for the graph edges; OSM class for colour |
| `iso_02_layer_stack.svg` | Four planes over one geography — static features, intervention, response, uncertainty | intervention counts and mean \|response\| per link, over all 1,000 scenarios |
| `iso_03_pipeline.svg` | The six pipeline stages as isometric slabs | figures asserted by `scripts/verify_headline_results.py` |

## On `.drawio` sources

These three are **generated from data, so the script is the editable source** — a `.drawio`
file would be a frozen copy that silently goes stale the moment the corpus changes. Hand
drawing 5,200 real coordinates is not practical, and approximating them would defeat the
purpose.

`.drawio` sources make sense for a schematic with no data behind it. If more diagrams of
that kind are added here, they should ship as `.drawio` plus an exported SVG.

## Old versus new

Both sets were rendered and inspected. Recommendation per diagram:

| Topic | Existing (`docs/diagrams/`) | Isometric | Recommendation |
| --- | --- | --- | --- |
| Research problem | `01_research_problem.svg` — precise boxes, states the gap and the contribution | — | **KEEP OLD.** Nothing to gain from an isometric treatment of an argument. |
| Dataset pipeline | `02_dataset_pipeline.svg` — marks which stages were retained | — | **KEEP OLD.** The greyed unretained stages carry information a slab cannot. |
| Feature anatomy | `03_feature_representation.svg` — full statistics table | — | **KEEP OLD.** A table is the right form for eleven measured fields. |
| Line graph construction | Panel inside `03` — small schematic of three links | `iso_01_graph_lifting.svg` | **KEEP BOTH.** The schematic explains the idea in one glance; the isometric proves it on the real network. Use the schematic first, the isometric as the payoff. |
| Model architecture | `04_model_architecture.svg` — layer widths from the checkpoint | — | **KEEP OLD.** Exact shapes matter more than depth here. |
| Training and evaluation | `05_training_evaluation.svg` | — | **KEEP OLD.** |
| Uncertainty pipeline | `06_uncertainty_pipeline.svg` | — | **KEEP OLD.** |
| Evaluation framework | `07_evaluation_framework.svg` — four questions and how they relate | — | **KEEP OLD.** |
| End-to-end pipeline | — | `iso_03_pipeline.svg` | **NEW, no old equivalent.** Six stages in one line, each carrying a verified figure. |
| Data layers over one geography | — | `iso_02_layer_stack.svg` | **NEW, no old equivalent.** The clearest available statement that intervention and response do not coincide spatially. |

**Nothing is recommended for deletion.** The two sets do different work: the existing set
explains structure and exact quantities, the isometric set shows scale and spatial
relationship on real data. `iso_01` and the `03` schematic are the only genuine overlap,
and they are complementary rather than redundant.

For a portfolio page, `iso_02_layer_stack.svg` is the strongest single hero candidate — it
is immediately legible as a city and it carries the thesis's central finding without
requiring any text.
