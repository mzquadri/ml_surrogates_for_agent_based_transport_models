## B. Cross-File Data Flow Notes

### B1. Producer Script Breakdown
- **`figures/generate_phase3_figures.py`** produces 5 of the 10 JSONs:
  - conformal_conditional_coverage_t8, reliability_diagram_t8, temperature_scaling_t8 (Tier 1)
  - per_graph_variation_t8, stratified_uq_t8, t7_error_detection (Tier 2)
- **Dedicated producer scripts** for the other 4:
  - `scripts/compute_pit.py` -> pit_t8.json
  - `scripts/compute_pit_after_tempscaling.py` -> pit_after_tempscaling_t8.json
  - `scripts/regenerate_fig58_s30.py` -> selective_prediction_s30.json
  - `scripts/run_s_convergence.py` -> s_convergence_results.json

### B2. Authoritative Figure Scripts
Each Tier 1 JSON has exactly ONE authoritative figure consumer:
- `conformal_conditional_coverage_t8.json` -> `figures/run_fig56.py` -> `t8_conformal_conditional.pdf`
- `selective_prediction_s30.json` -> `run_fig58.py` -> `t8_selective_prediction_curve.pdf`
- `reliability_diagram_t8.json` -> `run_fig511.py` -> `t8_reliability_diagram.pdf`
- `temperature_scaling_t8.json` -> `run_fig512.py` -> `t8_temperature_scaling.pdf`
- `pit_t8.json` -> `run_fig513.py` -> `t8_pit_histogram.pdf`
- `s_convergence_results.json` -> `run_fig61.py` -> `t8_s_convergence.pdf`

### B3. Special Cases
1. **`pit_after_tempscaling_t8.json`** is an OUTPUT artifact, not an input.
   The figure `t8_pit_after_tempscaling.pdf` is generated by `scripts/compute_pit_after_tempscaling.py`
   directly from raw NPZ data (`mc_dropout_full_100graphs_mc30.npz`) + hardcoded `T_OPTIMAL = 2.7025`.
   The JSON is saved as an audit/summary artifact alongside the figure. No script reads it to generate a figure.

2. **`run_fig518.py`** does NOT read `t7_error_detection.json` or any other JSON.
   It uses 100% hardcoded values (T7 dict lines 29-39, T8 dict lines 40-50) with 18 inline assertions.

3. **`per_graph_variation_t8.json` and `stratified_uq_t8.json`** are produced AND consumed within the same script
   (`generate_phase3_figures.py`). The JSON is saved as an intermediate artifact, and the figure is generated
   in the same function invocation. The `generate_all_hd_plots.py` script also reads them independently.

4. **`t7_error_detection.json`** is read by `run_fig515.py` (lines 115-119) as a cross-reference for
   T7 rho validation, but the main figure data comes from raw T7 NPZ files.

### B4. Common Consumer Scripts (appear across all 10 files)
- `scripts/audit_data_integrity.py` — reads all 10 for existence/integrity checks
- `scripts/generate_all_hd_plots.py` — reads all 10 for HD plot generation
- `scripts/verify_all_metrics.py` — reads 8 of 10 (not per_graph_variation, not t7_error_detection directly)
- `scripts/verify_all_numbers_final.py` — reads 6 of 10

### B5. Non-Authoritative/Superseded Consumers
- `figures/generate_phase3_figures.py` also generates figures for some of the same stems as the
  `run_fig*.py` scripts (e.g., reliability_diagram, temperature_scaling, conformal_conditional,
  t7_vs_t8 comparison). The `run_fig*.py` scripts are **authoritative** (use verified JSON + assertions);
  the `generate_phase3_figures.py` versions are **superseded** for those figures.
- `scripts/generate_s_convergence_figure.py` and `verify_fig61.py` use **hardcoded absolute paths**
  (Windows raw strings) — both are supplementary/verification scripts, not authoritative generators.
